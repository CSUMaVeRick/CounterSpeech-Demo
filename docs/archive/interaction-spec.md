# 社交媒体实验交互规格（讨论稿）

此页归档原始交互设计稿。当前实现见[项目首页](../../README.md)，早期配置见[实验示例](../../configs/examples/experiment.example.json)。

## 1. 已确定的范围

- Streamlit 管理实验流程，单个自定义网页组件呈现社交媒体交互。
- 每次实验环境指定一种主题，参与者不能切换；支持小红书、微博、抖音、哔哩哔哩、知乎风格。
- 五种主题共用内容 ID、回复关系、事件语义及展示规则。主题可以调整布局、配色、图标及操作文案。
- 手机与电脑自适应，保持配置的评论顺序。
- 每帖有 10 条预设评论。当前约定总数包含顶层评论及嵌套回复，待研究团队确认。
- 研究者控制帖子、初始赞数、评论树与各层显示顺序。Counter speech 必须实际展示。
- 本稿只处理实验交互；招募、完整问卷、量表及正式刺激材料编写不在本轮范围内。

## 2. 参与者路径

进入实验 → 接收固定配置与参与者匿名标识 → 信息流 → 目标帖详情 → 浏览评论及自主互动 → 达到展示条件 → 完成并返回问卷。

信息流中的“打开评论”进入详情；详情直接展开评论区。参与者可返回信息流，不清空进度。结束按钮置于平台内容外的实验导航区域，未满足条件时说明“请继续浏览评论后完成本环节”，不标出哪条是 counter speech。

本示例只有一个目标帖。以后出现多个必看帖时，每帖分别满足要求后才可完成。

## 3. 布局草图

手机：

```text
┌─────────────────────────┐
│ 平台风格导航             │
├─────────────────────────┤
│ 作者 · 时间              │
│ 帖子正文／可选图片       │
│ 点赞       评论          │
├─────────────────────────┤
│ 评论区（固定顺序）       │
│ 顶层评论 A               │
│   回复 A1                │
│   回复 A2 → 回复 @对象   │
│ 顶层评论 B               │
│ ……                      │
├─────────────────────────┤
│ 回复编辑区               │
└─────────────────────────┘
  实验导航／完成本环节
```

电脑：

```text
平台导航 │ 居中的帖子与评论内容列 │ 可选装饰区域
         │ 作者／正文／操作栏     │
         │ 评论树／回复编辑区     │
         │ 实验导航               │
```

抖音风格使用深色内容区：手机采用底部评论面板，电脑采用右侧评论面板。进入详情即打开面板，面板内独立滚动也须计入可见性检测。不要求提供视频；本轮可使用文字／图片内容，不伪造可播放按钮。

小红书为红色图文卡片；微博为橙色信息流；哔哩哔哩为粉蓝详情页和楼层回复；知乎为蓝色文字详情。第一版不追求像素级复刻，不使用真实用户资料。

窄屏最多呈现两级视觉缩进，更深关系通过“回复 @用户名”表示，数据仍保留完整树。按钮具备可读标签、触屏点击区域、键盘焦点及选中状态；正文允许换行，固定编辑区不能遮住末尾评论。

## 4. 评论树与顺序

每条评论使用稳定的 ID、父评论 ID 和同级序号。顶层父 ID 为 null；序号只在同一父级内比较。按树前序显示，不根据赞数或参与者互动重新排序。

示例树（共 10 条）：

```text
c01
├─ c02
└─ c03
   └─ c04
c05
c06
├─ c07（counter speech）
└─ c08
c09
c10
```

预设评论全部默认展开。研究者角色标记只保留在服务端，前端仅接收需要呈现的数据；必展示目标通过普通内容 ID 指定，不显示研究标签。参与者新增评论在单独的“我的评论”区域显示，不插入预设树，避免改变预设顺序；这一区域的位置与样式在各条件中保持一致。

## 5. 必展示规则

“加载成功”不等于“展示成功”。当前建议以配置指定的评论为目标，要求目标正文至少 50% 的区域连续可见 2 秒；这是待预测试的起始值，不是研究结论。

- 同时要求页面处于前台、目标分支和评论面板打开；被固定工具栏覆盖的区域不计入有效视口。
- 切换标签页、离开详情或低于可见比例时，连续计时重新开始。
- 每个必展示目标均满足后才解锁完成。允许继续互动或返回，已达成的记录保留。
- 不自动滚动、不置顶、不突出标记目标评论，保留研究者指定的位置。
- 预测试检查最长目标评论在最小支持视口中能否达到阈值；不能达到时调整规则或材料，再开始正式采集。
- 完成请求由服务端核对已保存的展示事件；浏览器测量仍只能作为展示机会的证据，不能证明阅读，也不能完全排除客户端伪造。

## 6. 按钮行为

| 操作 | 行为 |
| --- | --- |
| 帖子／评论点赞 | 切换本人点赞状态；显示初始赞数加本人贡献，不影响其他参与者 |
| 评论入口 | 打开帖子详情和评论区 |
| 回复 | 指定回复对象、输入、提交；空白内容拒绝，默认最多 500 字符 |
| 取消编辑 | 关闭编辑器，保留本地草稿；草稿默认不上传 |
| 展开／收起回复 | 默认关闭此功能以保证树完整展示，后续如启用须额外处理展示规则 |
| 完成本环节 | 检查必展示条件、保存并确认成功后跳转；保存失败留在当前页并允许重试 |

第一版只启用点赞、评论与回复。转发、收藏、举报暂不出现；若后续启用，应明确为实验内模拟并记录动作，不能跳转真实平台。每个看起来可点击的按钮都必须有实际反馈。

## 7. 配置与数据边界

示例 JSON 分为 environment、stimuli、conditions。第一版可以放在一个文件，避免过早拆分。

- environment：主题、允许交互、展示阈值、匿名完成路由。
- stimuli：人物、帖子、评论、初始赞数、研究者角色标签。
- conditions：使用的帖子及评论树、必展示目标。示例只有 baseline 一个条件，不预设正式分组或分配方法。
- 每位参与者首次进入时固定实验版本、配置快照／哈希、条件、平台主题及实际树顺序；恢复时仍用原配置。
- 正式采集前锁定配置版本，修改材料产生新版本。JSON 中不存密钥、参与者数据或数据库凭据。

正式存储优先使用事务数据库；单机试用可以用 SQLite，多实例部署再采用 PostgreSQL。JSON 只作为材料和配置来源。

配置加载时拒绝：未知主题、重复 ID、引用缺失、跨帖回复、循环／不可达评论、同级序号重复、每帖预设评论不是 10 条、必展示目标未包含于该条件、负赞数、无效阈值。用户输入以纯文本呈现，禁止作为 HTML 执行。

## 8. 行为记录及恢复

每个事件包含 event_id、匿名 participant_id、session_id、实验／条件／配置版本、事件类型、目标 ID、客户端时间、客户端单调时钟时间、服务端接收时间、单调递增序号及必要载荷。客户端时钟不用于跨参与者精确比较。

记录：进入实验、打开／离开帖子、目标可见区间、展示达成、点赞／取消、评论提交、阶段完成。可见性按区间记录，不逐帧上传。评论只保存已提交文本，不采集按键、未提交草稿或剪贴板。

同时保存最终点赞状态与已提交评论。事件 ID 去重；点赞提交明确的新状态，不用“再切换一次”的命令，防止重试反转结果。提交评论与事件在同一事务落库。未收到保存确认时显示待保存状态，重试使用原事件 ID。

Session State 只作运行时状态；匿名恢复令牌关联服务端进度，页面刷新后恢复原条件、操作与展示进度。令牌不含姓名等个人信息，不暴露在日志或返回问卷链接中。展示连续计时在刷新后重新开始，已完成的目标无需重看。精确滚动位置恢复暂不承诺。

## 9. 开发顺序和验收

1. 确认示例配置和两端草图，选一个主题打通交互、保存及恢复。
2. 增加其余四个主题，复用相同行为逻辑。
3. 预测试实际展示阈值、内容长度、按钮可用性及完成流程。

最小验收：五种主题的相同评论树顺序一致；手机无横向溢出；嵌套目标必须实际可见才解锁；后台标签页不计时；点赞重试不重复增减；回复重试不重复创建；刷新不重新分组；保存失败不显示完成；不同参与者互不影响。

## 10. 待研究团队确定

- 10 条是否确实包含所有层级回复。
- 平台首选主题及正式帖子数量。
- 50% 连续 2 秒是否采用，或在预测试后调整。
- 是否需要转发／举报等其他交互，以及新增评论是否采用单独区域。
- 正式实验条件、刺激材料及问卷衔接方式。
