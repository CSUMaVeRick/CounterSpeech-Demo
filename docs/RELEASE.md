# 合作者演示版 0.1.1

0.1.1 修复公网 HTTP 访问时 `crypto.randomUUID is not a function` 导致的启动失败。前端统一使用浏览器原生 `crypto.getRandomValues` 生成随机标识，保留已有会话令牌及待发送事件。此补丁不改变实验材料或清空数据库；HTTP 仍没有传输加密。增加了缺少 randomUUID 时的启动及旧会话重连回归检查。

以下记录为 0.1.0 的材料准备情况，数据重置仅在当时执行，更新到 0.1.1 不会再次执行。

本地准备日期：2026-10-25。固定配置：`configs/study.json`，配置版本 `collaborator-demo-20261025-v1`。

## 内容

- 两个条件：local_province、other_province。
- 两个帖子：按研究者最后预览的顺序展示 p02、p01。
- 6 个模拟用户，包含恢复的 u06 及其动态省份属地。
- 前测保留居住地及研究者新增的 pre_q01，后测保留已有题目。
- p02 的 10 条评论已更换文案，并对作者、初始赞数、相对时间和显示顺序做一次固定扰动。调整种子为 20261025，最终结果直接保存为 JSON，参与者进入时不会再次洗牌。
- 两个距离条件使用相同帖子、评论树、评论顺序与赞数，仅变量规则不同；指定反驳评论 p02_c07 继续作为必展示目标。

## 预设恢复与保存修复

p02、u06 和新增前测题此前只存在于管理预览的未提交会话配置中，未写入独立的预设文件。本版从最新的未提交模板快照恢复了这些预设，没有复制被试回答、事件、完成码或恢复令牌。

管理端新增／应用编辑后，会自动落盘到 `data/admin.work.json`，支持刷新和重启后继续编辑；它允许暂时不完整的工作状态。点击“校验并发布配置”才将通过检查的配置写入 `data/study.draft.json` 供参与者入口读取。工作草稿和运行配置分开。

代码仓库中的 `configs/study.json` 是此次分享的固定版本；管理端运行数据和草稿位于被 Git 忽略的 data/，不会随分享包分发。

## 数据重置

已按请求清空三个回收数据库：正式、演示、管理预览。清理前先恢复预设，并核验清理过程没有改变预设 JSON。没有保留回收数据备份；新会话首次进入时会重建空数据库。
